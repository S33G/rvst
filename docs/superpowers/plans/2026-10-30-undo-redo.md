# Shared undo/redo implementation plan

**Goal:** Provide per-instance editor undo/redo in RVST runners, including custom
editors, without plugin DSP changes or audio-thread history work. Save undo and
redo history with native DAW projects, as requested by the user.

**Architecture:** A shared `EditHistory` lives with each native parameter mirror.
`HistoryHost` decorates raw `EditorHost` calls. Runners retain that decorator across
frames; the shared handle retains committed actions across native window lifetimes.
Default-compatible trait methods expose status, undo/redo and explicit groups.

## Tasks

- [x] Core: add bounded parameter/state history, gesture coalescing, grouped edits,
  undo/redo via the raw host, no-op filtering, redo branching and atomic invalidation.
  Test automation isolation, preset failures, memory limits and reopened editors.
- [x] UI: add shared controls and frame shortcut handling, preserve text-editor
  undo, group parameter resets, test mouse/keyboard input and errors headlessly.
- [x] Native: retain history on `ParameterMirror`, expose it through raw hosts,
  and reject stale pending edits. Persist both stacks in a versioned state
  envelope, validate before plugin mutation, and accept legacy raw state.
  Test coherent saves, restoration and real-time boundaries without audio locks.
- [x] Runners: wrap native and WASM hosts once and use shared frame rendering.
  Verify the actual runner construction paths and browser target compilation.
- [x] Integration: run formatting, full workspace tests with all features, Clippy,
  WASM check, doc links, and fresh generated-project validation. Review the diff
  independently and document any unavailable DAW/platform evidence.

## Constraints

History travels alongside opaque plugin state, separately from the DAW's global
undo stack. Editor preset snapshots remain raw, avoiding recursive envelopes.
Do not record host playback automation. Replay parameter changes through existing
format notifications, not directly into DSP. Preserve prior skill/doc changes.
No publishing or claims of DAW qualification follow from source tests.

## Validation completed

On macOS arm64, 2026-10-30:

- `cargo test --workspace --all-features --locked`: 178 tests passed, excluding
  repeated filtered child-process checks. Loopback inspector tests ran outside
  the filesystem sandbox.
- `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`
  and `cargo fmt --all --check`: passed.
- `cargo check -p rvst-web --target wasm32-unknown-unknown --locked`: passed.
- `python3 scripts/check-generated.py --vendor-sdk`: all five variants passed
  locked offline builds, DSP tests and Clippy without changing their lockfiles:
  gain, instrument, pure MIDI, MIDI pass-through and debug.
- Documentation and skill metadata/link checks passed.
- Actual WASM editor input verified drag undo/redo, grouped reset undo/redo and
  preset recall undo/redo. Headless tests cover text focus and shortcuts during
  a drag. Native state callbacks test project reopening, both history stacks,
  mid-drag saves, rejected loads, stale events and audio/UI handoffs.
- Independent core, native and UI reviews completed; reported defects fixed and
  covered by regression tests.

No DAW qualification or Windows/Linux host validation was performed. Existing
plugin binaries require an SDK update and rebuild to receive this feature.
